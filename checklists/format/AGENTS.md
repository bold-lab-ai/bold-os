# AGENTS.md — Format checklist (authors)

For a coding agent helping a **paper's author** clear BOLD Lab's Format checklist before Draft & Review closes. This is a pre-check, not a substitute for ticking the boxes — the author (any listed co-author) still ticks the real checklist at the paper's card on the [Internal Review Board](https://bold-lab-ai.github.io/ml-conference-cycle/audit-board.html), which is what actually gates the card from Drafted to Reviewed. This file only covers the Format checklist; the Science checklist is a separate pass by the assigned reviewers — see `checklists/reviewers/AGENTS.md`, not this one.

## What you need before starting

- The paper's compiled PDF (not just the `.tex` source — anonymity and formatting both depend on what actually renders).
- The `.tex` source and any linked code/data repo, if you have access — several items below can't be checked from the PDF alone.
- The venue's own call-for-papers / author-instructions page for this submission — specifically its page limit, required template, and anonymity/dual-submission policy. Ask the user for the link if it isn't obvious from the paper itself; don't assume a generic ICLR/NeurIPS-style policy applies without confirming which venue and year this actually is.

## The six items, and how to check each

Work through all six regardless of whether an earlier one failed — report every finding, don't stop at the first problem.

1. **Mandatory sections & parts.** All required sections and disclosure forms are present and actually filled in, not left as templates (limitations, ethics statement, paper checklist, broader impact — whichever the venue requires), and everything the main text cites in the appendix actually exists there. Check: read the venue's own required-sections list, then confirm each exists in the PDF with real content (not a copied placeholder sentence). Grep the main text for every `\S` or "Appendix X" cross-reference and confirm the target section exists.
2. **Length & page limits.** Main paper and every section-specific limit (abstract word count, appendix page count, etc.) are within bounds — without manually shrinking margins, font, or spacing to cheat more content in. Check: count pages of the body text against the stated limit (references/appendix are usually excluded — confirm which). Diff the paper's preamble against the official template's for `\vspace`, `\small`/`\footnotesize`, margin, or font-size overrides that aren't part of the template itself.
3. **Double-blind anonymity — inside the PDF.** No author names or affiliations anywhere (including acknowledgments), and nothing identifying in the file's own title/author metadata. Check: full-text search the PDF for the authors' names, institutions, and email domains (ask the user for the real author list to search for — the anonymized PDF obviously won't have it in visible text if it's already been stripped, so this step is about catching what *wasn't* stripped). Read the PDF's embedded metadata (`pdfinfo`/`exiftool` — Title/Author/Producer/Creator fields) for anything identifying.
4. **Double-blind anonymity — outside the PDF.** Linked code/data repos are anonymized (README, commit history, filenames) and self-citations are phrased in the third person. Check: if there's a linked repo, look at its README for author names, check `git log` authorship isn't exposed (or that it's a fresh anonymized copy, not the real dev history), and scan filenames for anything identifying. Check every self-citation in the bibliography reads as "prior work by [Author] et al." rather than "our earlier work" or "we previously showed."
5. **Template & formatting.** Latest official venue template (not a copy from a previous year), compiles cleanly with no missing figures, broken references, or warnings, and fonts/page size are correct. Check: confirm the `\documentclass`/style file matches the current year's official template (diff against a fresh download if possible — a stale copied template is a common, easy-to-miss mistake). Actually compile the source and check the log for warnings, undefined references (`??` in the PDF), or missing figure files.
6. **Policy compliance.** Not in violation of the venue's dual-submission/prior-publication policy, and any arXiv or preprint posting follows its timing policy. Check: ask the user directly whether this paper (or a close variant) is under review or already published elsewhere, and whether/when it's been posted to arXiv — then compare against the venue's stated policy text, don't assume.

## Reporting

For each of the six items, give a clear **pass / fail / can't verify** plus a one- or two-sentence reason citing the specific page/section/line that backs it up — a human should be able to jump straight to the evidence, not re-derive it. Don't soften a fail into a pass because most of an item is fine; partial compliance is still a fail for that item.

You very likely don't have a signed-in session to the Internal Review Board itself, so you can't tick the boxes directly — hand your report to the author to tick by hand, or, if you're operating inside the author's own already-authenticated browser session, the same pattern `docs/FIREBASE.md` documents for one-off data fixes (a small script against `firebase.firestore()`) applies here too, gated exactly the same way the app itself gates it: only a listed co-author's signed-in email can write `authorChecked` on this paper's card.
